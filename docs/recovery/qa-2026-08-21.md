## Environment and method

- Target: `recovery-production-source-2.franciscabustos.pages.dev`
- Tool: locally installed `agent-browser` with Chrome for Testing
- Viewports: desktop `1440×900`; mobile `390×844`
- Evidence: 20 viewport screenshots retained locally in a temporary QA artifact
  directory; not committed because they are generated review artefacts.
- Test type: read-only rendering/navigation. No form data was entered and no
  CTA or submission that could create a booking/payment was activated.

## Visual observations

- Home and Sobre mí render correctly at the captured viewport in desktop and
  mobile. Header navigation, hero text, responsive menu control, CTA layout,
  and cookie banner were visible without horizontal overflow.
- The browser DOM reported one image with zero natural dimensions on desktop
  Home and on Sobre mí. The visible hero imagery rendered, so this appears to
  be a deferred/offscreen resource rather than a confirmed visual break. It is
  a follow-up item, not a production change made here.
- No accessibility audit was run beyond obvious visual blockers. Keyboard,
  screen-reader, form-label, and semantic-flow QA remain pending.

## Reservation safety exception

`/reserva` was deliberately not loaded. Static inspection proves that
`assets/booking.js` performs a direct availability `GET` to an embedded Apps
Script URL as the page initializes. Loading it would violate the safety rule
against triggering upstream requests from a preview that is not proven
isolated. Consequently, reservation UI, payment flow, form QA, and return-flow
QA are **BLOCKED**, not passed.

## Limits

This result does not verify booking, payment, webhook, Calendar, email,
analytics payloads, canonical behavior, redirects, robots, sitemap, or
production. Those tests require the isolation plan to be implemented and
approved first.
